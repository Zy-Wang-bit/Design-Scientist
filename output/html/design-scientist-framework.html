Framework Brief

不是普通实验流水线，而是会持续改进计算设计方法的 Research OS。

Design Scientist 面向 wet-lab variant design：已有多轮实验数据、目标明确、约束真实存在，并且每一轮新数据都要更新长期研究状态，而不是让策略从零开始。

框架分成两种工作模式：Framework R&D 负责发明、实现、对照和消融新的计算设计方法；Project execution 使用当前通过验证的方法，为具体项目产出候选池、推荐面板和 human review packet。

System Architecture

五层结构把参考仓库、文献、方法节点、benchmark 和真实项目交付拆开。

关键设计原则是：参考材料只读、方法节点隔离、结论必须落到 artifact，最终裁判由 deterministic benchmark 和 validation 完成。

Reference layer
保留 AI-Scientist、AI-Scientist-v2 和 DeepScientist 作为只读参考，通过 audit-references 生成可追踪的 reference artifacts。
Research OS layer
每个长期任务被初始化成 quest，维护 quest.yaml、research_map.json、findings memory 和 failure memory。
Literature layer
文献检索、paper card 标准化、method module 抽取和 method registry 共同构成方法发明的输入。
Scientist manager
把一次 scientist run 拆成 baseline reproduction、ideation、implementation、repair、ablation、selection 和 report。
Design kernel
核心 experiment 不是训练模型，而是选择 candidate selection policy，在 synthetic multi-world replay 中比较策略表现。

Persistent Design Loop

每轮新数据进入同一个状态更新循环，避免策略记忆只停留在对话里。

这个循环既服务 Framework R&D，也服务 Project execution。区别只在于前者评估方法，后者把当前可信方法用于实际候选推荐。

standardized data 只读取 data contract 允许的标准化表。
evidence update 构建 evidence cards，标注证据层级和限制。
design state 更新长期项目状态，而不是重启研究策略。
candidate generation 使用明确 operators 生成候选和对照。
panel selection 按预算选择下一批实验面板。
validation 检查 unsupported claims、identifier 和 artifact 完整性。
new data merge 新数据先进入 schema audit，再进入下一轮状态。

Evidence Discipline

生命科学设计里，claim 的边界比页面好看更重要。

框架把 evidence 明确分层，禁止把近似证据、描述事实或模型推导包装成因果结论。anti-HBsAg 示例里，sdAb 和 1E62 的角色也被分开处理。

primary_matched

精确匹配的主要实验对比，可用于强证据判断，但仍需保留来源和轮次。

secondary_near_matched

近似匹配证据，只能支持受限判断，不能直接上升为模块因果结论。

descriptive / model_derived

描述性事实或模型生成信息，必须和真实实验观察分开标注。

Identifier guard: 框架显式保护 1E62 这类 identifier，避免 pandas 或 CSV 工具把它误读成科学计数法 1e+62。validation 会拒绝残留错误 identifier 的 artifact。 
select_batch(observed, candidates, budget, round_index, rng) -> list[str]

Deterministic Benchmark

LLM 可以生成和批判方法，但不能用解释替代选择结果。

所有策略必须通过同一个 policy API，在相同输入、预算、模拟世界和指标下比较。selected method 需要在多数 synthetic worlds 中击败 baseline，并且不能退化成 baseline clone。

5 synthetic worlds: additive、epistatic、confounded transfer、noisy endpoint、sparse early round。
2+ 最低 baseline 对照：random feasible 与 fixed mix，并检测 source baseline overlap。
0 不允许 unsupported claim 成为方法优势；false claim rate 不能变差。
1 最终 selected branch 进入 method report，失败路径写入 failure memory。
Artifact Why it matters
scientist_journal.json 记录文献快照、node、benchmark、selected node 和失败路径。
benchmark_results.csv 逐方法、逐 synthetic world 保存可比较指标。
novelty_report.json 检测 selection overlap 和 behavioral baseline clone。
method_report.md 把方法假设、证据、胜负、失败模式和下一轮建议写成人可审查报告。

Human Handoff

框架交付的是候选决策证据，不是自动下实验单。

Human review 是系统设计的一部分。尤其在真实 wet-lab 前，panel recommendation 必须经过人工检查，确认数据、约束、证据层级和 unsupported claims 都可接受。

Quest 定义后 检查 domain、objective、可用数据和约束是否准确。
文献检索后 检查 paper cards 是否偏题，是否漏掉关键方法方向。
方法节点生成后 看 proposal 是否真的提出 acquisition、allocation、uncertainty 或 transfer 新机制。
Benchmark 后 检查 selected method 是否只是在某个 synthetic world 过拟合。
Validation error 时 人工决定修复数据、修复代码、降低 claim，还是停止推进。
真实实验前 审查 human_review_packet.md，再决定是否进入湿实验。
